# Требования к системе FinWallet

## Заказчик и цель

Условный заказчик — небанковская финансовая организация (оператор электронных денежных средств),
которой нужен прототип клиентского кошелька и кредитного калькулятора для демонстрации продукта
и обучения сотрудников.

## Функциональные требования

| ID | Требование |
|---|---|
| FR-1 | Регистрация клиента по логину, ФИО и паролю |
| FR-2 | Вход и выход; блокировка после 3 неудачных попыток подряд |
| FR-3 | Открытие счёта в рублях; номер из 20 цифр с контрольным ключом |
| FR-4 | Пополнение и снятие средств |
| FR-5 | Перевод между счетами с проверкой номера получателя |
| FR-6 | Просмотр баланса и истории операций только по своим счетам |
| FR-7 | Суточный лимит расходных операций 1 000 000 ₽ |
| FR-8 | Операции от 600 000 ₽ — на проверку, решение принимает сотрудник |
| FR-9 | Расчёт графика по кредиту (аннуитет / дифференцированный) |

## Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-1 | Точность денежных расчётов до копейки, без `float` |
| NFR-2 | Атомарность перевода, баланс никогда не отрицательный (CHECK в БД) |
| NFR-3 | Время обработки операции — не более 50 мс на сервере |
| NFR-4 | Повтор запроса не создаёт повторный платёж (идемпотентность) |
| NFR-5 | Пароли только в виде соли и хеша; сессия в HttpOnly, SameSite=Strict cookie |
| NFR-6 | Покрытие кода тестами не ниже 80 % |
| NFR-7 | Интерфейс на русском языке, работает на телефоне |

## Регуляторные ограничения (учтены в упрощённом виде)

* 152-ФЗ «О персональных данных» — минимизация данных, маскирование номеров счетов в журналах.
* 115-ФЗ «О противодействии легализации…» — порог обязательного контроля 600 000 ₽.
* 161-ФЗ «О национальной платёжной системе» — лимиты операций, журнал операций.
* Положение Банка России № 579-П — структура номера счёта и контрольный ключ.
* ГОСТ Р 57580.1-2017 — журналирование событий безопасности, управление доступом.
